## 📖 零、版本背景（必读）

### 0.1 26.1 —— 大型内容更新 "Tiny Takeover"（小小逆袭）

发布于 2026 年 3 月 24 日。

**核心主题：幼年生物大翻新**
- 为牛、哞菇、羊、猪、猫、豹猫、狼、鸡等被动型生物，以及僵尸、尸壳、溺尸、猪灵等敌对生物的幼年版本，更新了模型与纹理
- 为狼、猫、猪、马、鸡的幼年形态添加了全新音效
- 调整了多种幼年生物的碰撞箱

**关键新物品与机制**
- **金蒲公英 (Golden Dandelion)**：喂食幼年生物可暂停/恢复生长。合成配方为 1 个蒲公英 + 8 个金粒。不能用于幼年僵尸或幼年村民
- **可合成的命名牌**：1 张纸 + 1 个金属粒（铁、金或铜）。命名牌不再作为战利品出现在远古城市和林地府邸

**重要机制与性能改进**
- 默认内存从 2GB 提升至 4GB，垃圾回收器从 G1GC 更换为 ZGC
- **Java 版本要求：从 26.1 开始，必须使用 Java 25**
- 新音效：成年猫、猪、牛、鸡增加声音变种
- 新乐器：铜块上放置音符盒可发出小号声音，音色根据氧化程度变化
- 切石机配方：石头 → 圆石变种，深板岩 → 磨制/砖/瓦变种
- 数据包版本更新至 101，资源包版本更新至 84
- **首个完全去混淆 (fully unobfuscated) 的发布版本**
- 首个采用新版本号方案 `年.大版本.补丁` 的正式版

### 0.2 26.1.1 —— 热修复

发布于 2026 年 4 月 1 日。

- **修复关键漏洞 MC-307140**：26.1 中聊天功能启用时玩家无法举报他人聊天消息，26.1.1 恢复了该功能
- **仅客户端更新**：完全兼容 26.1 版本的服务端
- 无新增内容

### 0.3 26.1.2 —— 热修复

发布于 2026 年 4 月 9 日。

- 修复未公开的安全漏洞，其中一项是修复了旁观者模式玩家可以攻击实体的问题
- 对 UI 中的复选框 (checkbox) 样式进行了微调
- **兼容 26.1 和 26.1.1 的服务端**
- 无新增内容

### 0.4 版本兼容性

| 模组目标版本 | 26.1 | 26.1.1 | 26.1.2 | 26.2 |
| :--- | :--- | :--- | :--- | :--- |
| **26.1.x** | ✅ | ✅ | ✅ | ❌ |
| **26.2** | ❌ | ❌ | ❌ | ✅ |

**结论**：26.1.x 内部完全兼容，**26.2 是破坏性更新（混沌立方）**，不向后兼容。

## 📌 一、26.1.2 是什么？

### 1.1 版本号含义

| 版本号 | 含义 |
| :--- | :--- |
| **26** | 年度主版本号（2026 年） |
| **1** | 次要版本号（26.1.x 系列） |
| **2** | 补丁版本号 |

**注意**：26.*.* 系列从 `26.1` 开始，**不存在 26.0**。

### 1.2 与旧版（1.21.1 及以下）的核心区别

| 特性 | 旧版（1.21.1 及以下） | 新版（26.1.x） |
| :--- | :--- | :--- |
| **混淆状态** | 代码被混淆（类名如 `class_1234`） | **官方未混淆**（类名即原始名称） |
| **映射来源** | 需要 Yarn / 社区映射 | **官方映射（Official Mappings）** |
| **类名示例** | `net.minecraft.class_1234` | `net.minecraft.client.MinecraftClient` |
| **方法名示例** | `method_5678()` | `getInstance()` |
| **Loom 版本** | 旧版 Loom（如 0.x / 1.5.x） | **Loom 1.17.17+** |
| **插件 ID** | `fabric-loom` / `fabric-loom-remap` | **`net.fabricmc.fabric-loom`** |
| **Minecraft 坐标** | `net.minecraft:minecraft` | **`com.mojang:minecraft`** |
| **依赖关键字** | `modImplementation` / `modCompileOnly` | **`implementation` / `compileOnly`** |
| **JDK 版本** | JDK 17 / 21 | **JDK 25（必须！）** |

### 1.3 版本兼容性

| 模组目标版本 | 26.1 | 26.1.1 | 26.1.2 | 26.2 |
| :--- | :--- | :--- | :--- | :--- |
| **26.1.x** | ✅ | ✅ | ✅ | ❌ |
| **26.2** | ❌ | ❌ | ❌ | ✅ |

**结论**：26.1.x 内部完全兼容，但 **26.2 是破坏性更新（混沌立方）**，不向后兼容。

## 🔄 二、变量名变化对照表（从旧版迁移必看）

### 2.1 构建脚本（build.gradle）

| 旧版写法（1.21-） | 新版写法（26.*.*） | 说明 |
| :--- | :--- | :--- |
| `id 'fabric-loom' version '...'` | `id 'net.fabricmc.fabric-loom' version '...'` | 插件 ID 变了 |
| `id 'net.fabricmc.fabric-loom-remap'` | `id 'net.fabricmc.fabric-loom'` | 旧版 remap 插件已合并 |
| `minecraft "net.minecraft:minecraft:..."` | `minecraft "com.mojang:minecraft:..."` | 坐标变了 |
| `mappings "net.fabricmc:yarn:...:v2"` | **删除这行** | 新版默认官方映射，不需要手动配置 |
| `modImplementation "...fabric-loader..."` | `implementation "...fabric-loader..."` | 关键字变了 |
| `modCompileOnly` | `compileOnly` | 同上 |
| `modApi` | `api` | 同上 |
| `sourceCompatibility = JavaVersion.VERSION_21` | `sourceCompatibility = JavaVersion.VERSION_25` | JDK 版本变了 |

**总结**：需要改成 Gradle 标准类名，因为已经去除混淆（例如 Gradle 有个叫 `import` 的，以前是 `modImport`，现在是 `import`）。

### 2.2 代码中的类名（从 Yarn 迁移）

| 旧版（Yarn 映射） | 新版（官方映射） |
| :--- | :--- |
| `net.minecraft.class_1234` | `net.minecraft.client.MinecraftClient` |
| `net.minecraft.class_1234.method_5678()` | `MinecraftClient.getInstance()` |
| `net.minecraft.class_1234.field_4567` | `MinecraftClient.player` |
| `Identifier`（构造方法 `new Identifier("a", "b")`） | `Identifier.fromNamespaceAndPath("a", "b")`（静态工厂方法） |

### 2.3 参数名称（从 Yarn 迁移）

| 旧版（Yarn 映射） | 新版（官方映射） |
| :--- | :--- |
| `Identifier` 的 `namespace` / `path` | `Identifier` 的 `namespace` / `path`（相同，但构造方式变了） |
| `Registry` 的 `register` 参数 | 无变化 |

### 2.4 Gradle 属性名（gradle.properties）

| 旧版 | 新版 | 说明 |
| :--- | :--- | :--- |
| `yarn_mappings` | **删除** | 不再需要 Yarn 映射 |
| `loader_version=0.15.x` | `loader_version=0.19.3+` | 加载器版本需更新 |
| `loom_version=0.x` | `loom_version=1.17.17+` | Loom 版本需更新 |

```
│   ├── *****jar

│   ├── client/
│   │   └── java/              ← 客户端专用代码（含 MinecraftClient）
│   │       └── com/your/mod/
│   │           ├── ****.java
│   │           └── ****.java
│   └── main/
│       └── java/              ← 通用代码（不依赖客户端 API）
│           └── com/your/mod/
│               └── ****.java
└── fabric.mod.json
```

### 3.3 settings.gradle

```groovy
pluginManagement {
    repositories {
        maven {
            name = 'Fabric'
            url = 'https://maven.fabricmc.net/'
        }
        mavenCentral()
        gradlePluginPortal()
    }
}

rootProject.name = 'your-mod-name'
```

### 3.4 build.gradle

```groovy
plugins {
    id 'net.fabricmc.fabric-loom' version "${loom_version}"
    id 'maven-publish'
}

loom {
    splitEnvironmentSourceSets()
    mods {
        "your-mod-id" {
            sourceSet sourceSets.main
            sourceSet sourceSets.client
        }
    }
}

version = project.mod_version
group = project.maven_group

repositories {
    exclusiveContent {
        forRepository {
            maven {
                url "https://cursemaven.com"
            }
        }
        filter {
            includeGroup "curse.maven"
        }
    }
}

dependencies {
    // 注意：用 com.mojang，不是 net.minecraft
    minecraft "com.mojang:minecraft:${project.minecraft_version}"
    implementation "net.fabricmc:fabric-loader:${project.loader_version}"

    // 本地依赖：整个 libs/ 目录一次性引入
    implementation fileTree(dir: 'libs', include: '*.jar')

    implementation "curse.maven:melody-938643:7875748"
    include "curse.maven:melody-938643:7875748"
}

processResources {
    inputs.property "version", project.version
    filesMatching("fabric.mod.json") {
        expand "version": project.version
    }
}

tasks.withType(JavaCompile).configureEach {
    it.options.release = 25
}

java {
    withSourcesJar()
    sourceCompatibility = JavaVersion.VERSION_25
    targetCompatibility = JavaVersion.VERSION_25
}

jar {
    from("LICENSE") {
        rename { "${it}_${project.name}" }
    }
}

publishing {
    publications {
        create("mavenJava", MavenPublication) {
            from components.java
        }
    }
}
```

## 🔧 四、关键配置要点

### 4.1 插件 ID（必须用新 ID）

| 版本 | 插件 ID | 说明 |
| :--- | :--- | :--- |
| **26.1 及以上（未混淆）** | `net.fabricmc.fabric-loom` | ✅ 你当前使用的，无需额外 remap 插件 |
| 1.21.11 及以下（混淆版本） | `net.fabricmc.fabric-loom-remap` | 旧版混淆版本专用（已废弃） |
| `fabric-loom`（旧写法） | **仅向后兼容** | 不推荐显式使用，请用上方替代 |

### 4.2 Minecraft 坐标

| 版本 | 坐标 | 说明 |
| :--- | :--- | :--- |
| 26.*.* | `com.mojang:minecraft` ✅ | 官方未混淆版本 |
| 1.21 及以下 | `net.minecraft:minecraft` ❌ | 旧版混淆版本 |

### 4.3 映射（Mappings）

**核心原则**：26.1 开始，Minecraft 游戏代码**不再混淆**，类名就是源码中的原始名称（如 `net.minecraft.client.MinecraftClient`），因此**完全不需要配置任何映射（Mappings）**。

```groovy
// ✅ 正确：Loom 1.17+ 默认使用官方映射，无需额外配置
dependencies {
    minecraft "com.mojang:minecraft:${project.minecraft_version}"
    // 不要加 mappings 行！
}

// ❌ 错误示例 1：不要添加 Yarn 映射
// mappings "net.fabricmc:yarn:${project.yarn_mappings}:v2"

// ❌ 错误示例 2：不要调用任何 mappings 方法
// mappings loom.officialMojangMappings()
```

> 📌 **原理说明**：`loom.officialMojangMappings()` 是用于将混淆代码映射到 Mojang 官方名称的，而 26.1 的代码已经是官方原始名称，无需任何映射转换。Loom 1.17+ 默认行为即为"不应用任何混淆映射"，符合 26.1 的需求。

### 4.4 依赖关键字

| 旧版（1.21-） | 新版（26.*.*） |
| :--- | :--- |
| `modImplementation` | `implementation` |
| `modCompileOnly` | `compileOnly` |
| `modApi` | `api` |

### 4.5 本地依赖写法

```groovy
// ✅ 正确：使用 files（推荐）
implementation files('libs/xxx.jar')

// ✅ 正确：使用 name（需配合 flatDir）
repositories { flatDir { dirs 'libs' } }
implementation name: 'xxx'

// ❌ 错误：会与 Maven 依赖混淆
implementation ':xxx'
```

### 4.6 源码集分离

```groovy
loom {
    splitEnvironmentSourceSets()
}
```

| 代码类型 | 存放位置 |
| :--- | :--- |
| 客户端专用（含 `MinecraftClient`） | `src/client/java/` |
| 服务端专用 | `src/server/java/` |
| 通用代码 | `src/main/java/` |

## 🚨 五、常见错误及解决方案

### 5.1 `程序包net.minecraft.client不存在`

**原因**：客户端代码放在了 `src/main/java`，或 Loom 版本不正确。

**解决**：
1. 确保代码在 `src/client/java/` 下
2. 确认 `loom_version=1.17.17`
3. 确认 `minecraft "com.mojang:minecraft"` 而非 `net.minecraft`

### 5.2 `Could not find method officialMappings()`

**原因**：错误地在 `loom` 块外调用了 `officialMappings()`。

**解决**：删除所有 `mappings` 相关行，Loom 1.17+ 默认使用官方映射。

### 5.3 `MinecraftClient` 找不到但 jar 里有 class

**原因**：Loom 没有应用官方映射，或 Gradle 缓存损坏。

**解决**：
```bash
rmdir /s /q .gradle
rmdir /s /q build
rmdir /s /q C:\Users\Administrator\.gradle\caches\fabric-loom
g clean build --refresh-dependencies
```

### 5.4 `Declaring dependencies using multi-string notation has been deprecated`

**原因**：使用了 `implementation name: ('xxx')` 这种写法。

**解决**：改为 `implementation name: 'xxx'` 或 `implementation files('libs/xxx.jar')`。

### 5.5 未报告的异常错误 `MelodyAudioException` / `ALException`

**原因**：调用了可能抛出检查异常的方法，但没有捕获。

**解决**：添加 `try-catch` 或在方法上声明 `throws`。

### 5.6 `accessWidener` 文件头部报错（仅进阶用户）

如果你使用了访问加宽器（Access Widener）或类调整器（Class Tweaker），请检查文件头部：

```
# ❌ 错误（旧版写法）
accessWidener v2 named

# ✅ 正确（26.1+ 写法）
accessWidener v2 official
```

> **原因**：26.1 不存在"命名空间"概念（no named namespace），统一使用 `official`。

## 🏷️ 七、Fabric API 重命名快速参考（26.1 官方映射）

由于 Fabric API 在 26.1 中为了匹配 Mojang 官方名称，进行了大量重命名。以下是**最常用**的变化对照表：

| 旧名称（Yarn / 社区映射） | 新名称（26.1.2 官方映射） | 所属包 |
| :--- | :--- | :--- |
| `ClientTickEvents.START_WORLD_TICK` | `ClientTickEvents.START_LEVEL_TICK` | `net.fabricmc.fabric.api.client.event.lifecycle.v1` |
| `ClientTickEvents.END_WORLD_TICK` | `ClientTickEvents.END_LEVEL_TICK` | 同上 |
| `ClientWorldEvents` | `ClientLevelEvents` | 同上 |
| `ClientCommandManager` | `ClientCommands` | `net.fabricmc.fabric.api.client.command.v2` |
| `getWorld()`（在 `FabricClientCommandSource` 中） | `getLevel()` | 同上 |
| `BiomeSelectionContext.getBiomeRegistryEntry()` | `getBiomeHolder()` | `net.fabricmc.fabric.api.biome.v1` |
| `ServerWorld` | `ServerLevel` | 原版类名本身也变了（⚠️ 这不是 Fabric API 独有的，是整个游戏） |

> 📌 **完整列表**：由于重命名条目极多，完整清单请查阅 Fabric API 26.1 移植指南。

## 🏗️ 十二、模组主类与注册实战（ModInitializer + Registry）

### 12.1 主类模板（`ExampleMod.java`）

放在 `src/main/java/com/your/mod/ExampleMod.java`（通用代码）：

```java
package com.your.mod;

import net.fabricmc.api.ModInitializer;
import net.minecraft.item.Item;
import net.minecraft.item.ItemGroups;
import net.minecraft.registry.Registries;
import net.minecraft.registry.Registry;
import net.minecraft.util.Identifier;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class ExampleMod implements ModInitializer {
    public static final String MOD_ID = "yourmod";
    public static final Logger LOGGER = LoggerFactory.getLogger(MOD_ID);

    // 定义一个自定义物品
    public static final Item CUSTOM_ITEM = new Item(new Item.Settings());

    @Override
    public void onInitialize() {
```


### 14.2 写一个简单的 Mixin（注入 `MinecraftClient` 启动日志）

在 `src/client/java/com/your/mod/mixin/ClientExampleMixin.java`（**注意：客户端 Mixin 放 `client` 源集下**）：

```java
package com.your.mod.mixin;

import org.slf4j.LoggerFactory;
import org.spongepowered.asm.mixin.Mixin;

import org.spongepowered.asm.mixin.injection.Inject;
```

- 包名是否与 JSON 中 `package` 字段匹配；
- 是否将 Mixin 类放在了正确的源集（`client`/`server`/`main`）下。

## 📦 十五、依赖打包策略补充（针对 26.1.2）

### 15.1 什么时候用 `include`？

| 场景 | 写法 | 说明 |
| :--- | :--- | :--- |
| **只编译，不打包**（用户需自己装该库） | `implementation files('libs/xxx.jar')` | 适合大型 API（如 Fabric API） |
| **编译并打包进模组 JAR** | `include files('libs/xxx.jar')` | 适合小型库，避免用户额外安装 |
| **两者都写** | `implementation files(...); include files(...)` | 同时参与编译和打包（常见于兼容层） |

### 15.2 多 JAR 打包示例

```groovy
dependencies {
    // Fabric API —— 不打包（用户自己装）
    implementation "net.fabricmc.fabric-api:fabric-api:0.155.2+26.1.2"

    // 小型音效库 —— 打包进模组
    implementation files('libs/melody_mrt.jar')
    include files('libs/melody_mrt.jar')

    // CurseMaven 依赖同样适用
    include "curse.maven:melody-938643:7875748"
}
```

### 15.3 检查最终 JAR 是否包含依赖

```bash
jar tf build/libs/yourmod-xxx.jar | grep -E "\.(class|jar)$"
```

若看到依赖库的包名（如 `com/melody/...`），说明 `include` 生效。

```java
import net.minecraft.entity.Entity;
import net.minecraft.entity.player.PlayerEntity;

@Override
public void onInitialize() {

        if (entity.isAttackable()) {
            // 阻止攻击并返回取消
            return ActionResult.FAIL;
        }
        // 允许继续
        return ActionResult.PASS;
    });
}
```

### 17.2 生命周期事件（服务端启动/关闭）

```java
import net.fabricmc.fabric.api.event.lifecycle.v1.ServerLifecycleEvents;

@Override
```

## 📡 十八、网络通信（C2S / S2C 数据包，适配 26.1.2 新版 Payload）

> ⚠️ **重要**：26.1.2 使用 **`CustomPayload`** 接口替代旧的 `Identifier` 发包方式，不再使用 `NetworkHandler`。

### 18.1 定义数据包结构（通用代码，放在 `src/main/java`）

```java
import net.minecraft.network.RegistryByteBuf;
import net.minecraft.network.codec.PacketCodec;
import net.minecraft.network.codec.PacketCodecs;
import net.minecraft.network.packet.CustomPayload;
import net.minecraft.util.Identifier;

public record MyCustomPayload(String message) implements CustomPayload {
    public static final CustomPayload.Id<MyCustomPayload> ID =
        new CustomPayload.Id<>(Identifier.fromNamespaceAndPath("yourmod", "my_packet"));

    // 编解码器：定义如何序列化/反序列化
    public static final PacketCodec<RegistryByteBuf, MyCustomPayload> CODEC =
        PacketCodec.tuple(
            PacketCodecs.STRING, MyCustomPayload::message, // 编码消息字段
            MyCustomPayload::new                         // 构造方法
        );

    @Override
    public Id<? extends CustomPayload> getId() {
        return ID;
    }
}
```

### 18.2 客户端 → 服务端（C2S）发送

在客户端代码中（`src/client/java`）：

```java
import net.fabricmc.fabric.api.client.networking.v1.ClientPlayNetworking;

// 发送数据包
ClientPlayNetworking.send(new MyCustomPayload("你好，服务端！"));
```

### 18.3 服务端接收 C2S（在 `ModInitializer` 中注册）

```java
import net.fabricmc.fabric.api.networking.v1.ServerPlayNetworking;

@Override
public void onInitialize() {
    ServerPlayNetworking.registerGlobalReceiver(MyCustomPayload.ID, (payload, context) -> {
        // 必须在服务端线程中处理
        context.server().execute(() -> {
            String msg = payload.message();
            LOGGER.info("收到客户端消息: {}", msg);

            // 回复给客户端（S2C）
            ServerPlayNetworking.send(context.player(), new MyCustomPayload("服务端收到！"));
        });
    });
}
```

### 18.4 客户端接收 S2C（在 `ClientModInitializer` 中注册）

```java
import net.fabricmc.fabric.api.client.networking.v1.ClientPlayNetworking;

@Override
public void onInitializeClient() {
    ClientPlayNetworking.registerGlobalReceiver(MyCustomPayload.ID, (payload, context) -> {
        // 客户端线程处理
        String msg = payload.message();
        LOGGER.info("收到服务端消息: {}", msg);
    });
}
```

> 📌 **要点总结**：
> - 使用 `record` 定义不可变数据类；
> - 必须实现 `CustomPayload` 接口；
> - `PacketCodec.tuple` 按顺序绑定字段，字段数量需一一对应；
> - 支持的类型包括 `INT`、`STRING`、`UUID`、`BYTE_ARRAY` 等（见 `PacketCodecs` 类）。

## 🧩 十九、数据组件（Data Components）—— 替代旧版 NBT

26.1.2 完全采用 **Data Components** 系统（类似于 1.21+ 的设计），不再直接操作 `NBTCompound`。

### 19.1 为自定义物品添加数据组件

```java
// 定义组件类型（在 ModInitializer 中注册）
import net.minecraft.component.ComponentType;
import net.minecraft.registry.Registries;
import net.minecraft.registry.Registry;
import net.minecraft.util.Identifier;

public static final ComponentType<Integer> MY_CHARGE = Registry.register(
    Registries.DATA_COMPONENT_TYPE,
    Identifier.fromNamespaceAndPath(MOD_ID, "charge"),
    ComponentType.<Integer>builder().codec(Codec.INT).build()
);
```

### 19.2 在物品中使用组件

```java
// 自定义物品类
public class ChargedItem extends Item {
    public ChargedItem(Settings settings) {
        super(settings.component(MY_CHARGE, 0)); // 默认值 0
    }

    // 获取存储值
    public static int getCharge(ItemStack stack) {
        return stack.getOrDefault(MY_CHARGE, 0);
    }

    // 设置存储值
    public static void setCharge(ItemStack stack, int value) {
        stack.set(MY_CHARGE, value);
    }
}
```

### 19.3 常用内置组件

| 组件 | 用途 | 示例 |
| :--- | :--- | :--- |
| `DataComponentTypes.CUSTOM_NAME` | 物品自定义名称 | `stack.set(DataComponentTypes.CUSTOM_NAME, Text.literal("神剑"))` |
| `DataComponentTypes.LORE` | 物品描述（Lore） | `stack.set(DataComponentTypes.LORE, List.of(Text.literal("神器")))` |
| `DataComponentTypes.MAX_STACK_SIZE` | 修改最大堆叠数 | `stack.set(DataComponentTypes.MAX_STACK_SIZE, 99)` |
| `DataComponentTypes.ENCHANTMENTS` | 附魔列表 | `stack.set(DataComponentTypes.ENCHANTMENTS, EnchantmentHelper.get(...))` |

> ✅ **优势**：组件类型安全、序列化自动处理、与 JSON 数据包（如配方的 `result`）无缝集成。

## 🧭 二十二、26.1 核心变更速查（官方文档补充）

### 22.1 代码去混淆（最重要）

Minecraft 26.1 是首个完全不混淆代码的正式版本。这意味着：

| 变化 | 说明 |
| :--- | :--- |
| **类名即原始名** | `net.minecraft.client.MinecraftClient` 直接可见，不再需要 Yarn/MCP 映射 |
| **参数名保留** | 方法参数名也是原始名，不需要额外映射 |
| **Yarn 不再支持** | Fabric 官方不再维护 Yarn 映射，必须迁移到 Mojang 官方映射 |
| **所有旧模组需重编译** | 1.21.11 及之前的模组即使不改代码，也必须重新编译才能在 26.1 运行 |

### 22.2 工具链版本要求

| 组件 | 最低版本 | 说明 |
| :--- | :--- | :--- |
| **Java** | JDK 25 | 硬性要求，Gradle JVM 也必须用 25 |
| **Loom** | 1.15+（推荐 1.17.17+） | 必须用 `net.fabricmc.fabric-loom` 插件 ID |
| **Gradle** | 9.4.0+ | 旧版 Gradle 可能导致依赖解析异常 |
| **Fabric Loader** | 0.19.3+ | 26.1.x 推荐版本 |
| **IntelliJ IDEA** | 2025.3+ | 旧版对 Java 25 和 Mixin 支持不完整 |

### 22.3 OpenGL 淘汰时间表

- **26.1**：最后一个仅支持 OpenGL 的版本

## 🖥️ 二十三、HUD 渲染：HudElementRegistry（26.1 新标准）

### 23.1 基本用法

Fabric 提供 `HudElementRegistry` 来渲染和分层 HUD 元素。每个元素是一个 `HudElement`，通常是接受 `GuiGraphicsExtractor` 和 `DeltaTracker` 的 lambda。

```java
import net.fabricmc.fabric.api.client.rendering.v1.hud.HudElementRegistry;
import net.fabricmc.fabric.api.client.rendering.v1.hud.VanillaHudElements;
import net.minecraft.resources.Identifier;

public class MyHud implements ClientModInitializer {
    @Override
    public void onInitializeClient() {
        // 在聊天栏之前插入自定义 HUD 元素
        HudElementRegistry.attachElementBefore(
            VanillaHudElements.CHAT,
            Identifier.fromNamespaceAndPath(MOD_ID, "my_hud"),
            MyHud::extract
        );
    }

    private static void extract(GuiGraphicsExtractor graphics, DeltaTracker tickCounter) {
        // 绘制逻辑
    }
}
```

### 23.2 DeltaTracker 的作用

`DeltaTracker` 用于获取 `gameTimeDeltaPartialTick` —— 上一个游戏 tick 和下一个 tick 之间的"进度"值，用于**平滑插值动画**。

```java
// 方式一：获取 tick 插值（用于与游戏 tick 同步的动画）
float partialTick = deltaTracker.getGameTimeDeltaPartialTick(false);

// 方式二：获取真实时间（用于与时间同步的动画）——推荐
double currentTime = Util.getMillis() / 1000.0;
```

> 📌 **实践建议**：只有动画依赖 Minecraft tick 时才用 `gameTimeDeltaPartialTick`；时间驱动的动画用 `Util.getMillis()`。

### 23.3 与旧 API 的对比

| 旧版 | 26.1 |
| :--- | :--- |
| `HudRenderCallback.EVENT.register(...)` | `HudElementRegistry.addLast()` / `attachElementBefore()` / `attachElementAfter()` |
| `GuiGraphics` | `GuiGraphicsExtractor` |
| 渲染方法 `render()` | `extractRenderState()` |

## 🌐 二十四、网络通信：CustomPayload（26.1 标准写法）

### 24.1 定义数据包

26.1 使用 **`CustomPayload` 接口**（record 实现），不再使用旧的 `PacketByteBuf` 直接发包。

```java
import net.minecraft.network.RegistryFriendlyByteBuf;
import net.minecraft.network.codec.StreamCodec;
import net.minecraft.network.protocol.common.custom.CustomPacketPayload;
import net.minecraft.resources.Identifier;

public record MyPayload(String message) implements CustomPacketPayload {
    public static final CustomPacketPayload.Type<MyPayload> ID =
        new CustomPacketPayload.Type<>(Identifier.fromNamespaceAndPath("mymod", "my_packet"));

    public static final StreamCodec<RegistryFriendlyByteBuf, MyPayload> CODEC =
        StreamCodec.composite(
            ByteBufCodecs.STRING_UTF8, MyPayload::message,
            MyPayload::new
        );

    @Override
    public Type<? extends CustomPacketPayload> type() {
        return ID;
    }
}
```

### 24.2 注册与收发

```java
// 注册（必须在两端都注册）
PayloadTypeRegistry.playC2S().register(MyPayload.ID, MyPayload.CODEC);
PayloadTypeRegistry.playS2C().register(MyPayload.ID, MyPayload.CODEC);

// 服务端接收 C2S
ServerPlayNetworking.registerGlobalReceiver(MyPayload.ID, (payload, context) -> {
    context.server().execute(() -> {
        // 处理逻辑
    });
});

// 客户端发送
ClientPlayNetworking.send(new MyPayload("hello"));
```

> ⚠️ **关键**：数据包必须在注册接收器**之前**注册到 `PayloadTypeRegistry`。

## 📦 二十六、数据附件（Data Attachment）—— 替代直接 Mixin 存数据

### 26.1 是什么

Data Attachment API 允许开发者**在不写 Mixin 的情况下**，将任意数据附加到实体、方块实体、Level、Chunk 上。

### 26.2 基本用法

```java
public static final AttachmentType<String> MY_DATA = AttachmentRegistry.create(
    Identifier.fromNamespaceAndPath(MOD_ID, "my_data")
);

// 读写
entity.setAttached(MY_DATA, "hello");
String value = entity.getAttached(MY_DATA);
```

### 26.3 三种创建方式

| 方法 | 行为 |
| :--- | :--- |
| `AttachmentRegistry.create()` | 游戏重启后**清除** |
| `AttachmentRegistry.createPersistent()` | 游戏重启后**保留**（需 Codec） |
| `AttachmentRegistry.createDefaulted()` | 带默认值，用 `getAttachedOrCreate` 读取 |

### 26.4 同步与持久化

```java
AttachmentRegistry.create(
    Identifier.fromNamespaceAndPath(MOD_ID, "my_synced_data"),
    builder -> builder
        .initializer(() -> "default")
        .syncWith(ByteBufCodecs.STRING_UTF8, AttachmentSyncPredicate.all())
        .persistent(Codec.STRING)
);
```

### 26.5 全局附件（26.1 新增）

```java
// 不绑定到特定 Level 的服务器全局数据
Level.globalAttachments()        // 按 Level 获取
MinecraftServer.globalAttachments()  // 按服务器获取
```

## 🧩 二十八、Identifier 的正确用法（26.1）

官方文档明确推荐使用 **`Identifier.fromNamespaceAndPath(namespace, path)`**，而不是 `Identifier.of()`。

```java
// ✅ 正确（26.1 官方映射）
Identifier.fromNamespaceAndPath("mymod", "my_item");

// ⚠️ 也可以，但官方示例统一用 fromNamespaceAndPath
Identifier.of("mymod", "my_item");

// ❌ 错误（旧版构造方法）
new Identifier("mymod", "my_item");
```

> 📌 `Identifier.of()` 是 Yarn 映射时代的写法，`fromNamespaceAndPath()` 是官方映射的推荐方式。26.1 用官方映射，**统一用 `fromNamespaceAndPath`**。

## 📋 二十九、快速检查清单

在新项目或迁移时，逐项核对：

- [ ] `gradle.properties`：JDK 25、Loom 1.17.17+、Gradle 9.4+
- [ ] `build.gradle`：插件 ID = `net.fabricmc.fabric-loom`
- [ ] `build.gradle`：MC 坐标 = `com.mojang:minecraft`
- [ ] `build.gradle`：**无 `mappings` 行**
- [ ] 依赖关键字：`implementation` / `compileOnly` / `api`（无 `mod*` 前缀）
- [ ] 所有 `Identifier` 用 `fromNamespaceAndPath`
- [ ] HUD 用 `HudElementRegistry`（不是 `HudRenderCallback`）
- [ ] 网络包用 `CustomPayload` + `StreamCodec`
- [ ] 客户端 tick 事件用 `START_LEVEL_TICK` / `END_LEVEL_TICK`
- [ ] 数据存储优先用 Data Attachment（不是直接 NBT Mixin）
- [ ] `accessWidener` 头部用 `official`（不是 `named`）
